# Validation record: Azure, September 2026

[Back to validation and limits](../VALIDATION.md) · [Azure chapter](../13-azure.md)

On 28 September 2026 the Azure chapter and its example files were run end to
end in a disposable resource group, which was then deleted.

## How it ran

- **Subscription and region:** a sponsored subscription in `eastus2`, reached
  with an Azure CLI login that held the Contributor role.
- **Tooling:** the Azure playbooks ran from a workstation, in a separate
  virtual environment with ansible-core 2.21.4, `azure.azcollection` 4.0.0 and
  the collection's own requirement set (169 packages).
- **Controller:** Ubuntu 24.04 (`Standard_D2als_v6`), created by `controller.yml`
  and installed with the guide's Ubuntu installer at tag `v1.3.0`.
- **Targets:** Ubuntu 24.04 and AlmaLinux 9.8, created by `targets.yml` with
  cloud-init; and RHEL 9.8 (pay-as-you-go image), created with a plain
  `az vm create` and no custom data, to stand in for a VM that already exists.
  All three were `Standard_D2als_v6` with private addresses only, in the
  controller's VNet.
- **Secrets:** the sudo passwords were generated for the run and delivered on
  standard input; none appears in a command line or in the records.

## Found and fixed during the run

- On `localhost`, Ansible discovered the system Python instead of the virtual
  environment and could not import the Azure SDK. Each playbook now pins
  `ansible_python_interpreter` to `ansible_playbook_python`.
- The bootstrap playbook first read the controller's address from gathered
  facts, which under `become` hold root's environment; it now reads
  `SSH_CONNECTION` in a task without `become`.
- Public CI could not syntax-check or lint the Azure examples without the
  collection. It now installs the pinned collection, without the SDK, first.

## Not established

- Other regions, VM sizes, Trusted Launch VMs and Rocky Linux on Azure.
- Targets reached across a site-to-site VPN rather than inside one VNet.
- A controller-side managed identity; provisioning used a workstation CLI login.
- `azure.azcollection` versions other than 4.0.0.
