# Validation record: updating a controller, September 2026

[Back to validation and limits](../VALIDATION.md) · [Update a controller](../03-controller.md#update-a-controller-to-a-newer-guide-release)

On 28 September 2026, `scripts/update-controller.sh` and the seeder's template
tabs were tested on Azure in a disposable resource group, which was then
deleted.

## How it ran

- **Subscription and VMs:** the sponsored subscription of the
  [earlier Azure records](2026-09-azure.md), `eastus2`, `Standard_D2als_v6`.
- **Controllers:**
  - two AlmaLinux 9.8 VMs, each installed with the Enterprise Linux installer
    from tag `v1.4.0`, which seeds eleven templates, two variable groups and no
    tabs: the state of a controller installed before this release;
  - Ubuntu 24.04, installed with this branch's Ubuntu installer.
- **Target:** RHEL 9.8 pay-as-you-go, prepared with
  `examples/onboard/onboard-linux.sh` through Run Command with the controllers'
  service keys, and added to each with `add-target.sh`.

## Results

| Step | Result |
| --- | --- |

## Found and fixed

- An adversarial review of the first version found twelve problems, among them
  writes through predictable temporary names and links, a check that missed
  ignored and deleted files, a commit that took unrelated staged files, and
  Semaphore login after the folder had already changed. The updater was
  rebuilt: it checks the folder and logs in before changing anything, writes
  through folder handles that never follow a link, commits only its own files,
  resolves the project by its lab folder repository and file inventory rather
  than by name alone, and verifies each template it edits.
- The first live run of the rebuilt updater kept a committed `ansible.cfg`
  change, but a second run then replaced it, because it compared with the
  folder's own last commit. Updates now record the guide's versions in
  `.guide-files.json` and compare with those; the retest above kept the change
  through repeated runs.
- Run as root from an administrator's copy of the guide, Python left
  root-owned bytecode in that copy; the updater no longer writes any.
