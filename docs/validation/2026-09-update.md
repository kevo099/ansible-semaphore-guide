# Validation record: updating a controller, September 2026

[Back to validation and limits](../VALIDATION.md) · [Update a controller](../03-controller.md#update-a-controller-to-a-newer-guide-release)

On 28 September 2026, `scripts/update-controller.sh` and the seeder's template
tabs were tested on Azure in a disposable resource group, which was then
deleted.

## How it ran

- **Subscription and VMs:** the sponsored subscription of the
  [earlier Azure records](2026-09-azure.md), `eastus2`, `Standard_D2als_v6`.
- **Controllers:**
  - AlmaLinux 9.8, installed with the Enterprise Linux installer from tag
    `v1.4.0`, which seeds eleven templates, two variable groups and no tabs.
    This is the state of a controller installed before this release.
  - Ubuntu 24.04, installed with this branch's Ubuntu installer.
- **Target:** RHEL 9.8 pay-as-you-go, prepared with
  `examples/onboard/onboard-linux.sh` through Run Command with both
  controllers' service keys, and added to each with `add-target.sh`.

## Results

| Step | Result |
| --- | --- |
| Before the update | Ping succeeded through Semaphore on the `v1.4.0` controller. A playbook of the operator's own, `playbooks/my-own.yml`, was committed in its lab folder. |
| Plan | Listed three files to replace (`stig-apply.yml`, `stig-audit.yml`, `tasks/stig_scan.yml`), twelve guide files already current, `my-own.yml` as kept, `content/` to create, one variable group, three tabs and one template to add, and eleven templates to put on tabs. Nothing changed. |
| An uncommitted edit | With an edit to `stig-audit.yml` not committed, `--apply` refused and changed nothing. |
| Apply | Replaced the three files as the lab folder's owner, mode 0640, group `semaphore`, SELinux type `usr_t`; kept `my-own.yml`; created `content/` with mode 2750; made one commit; added the objects; and passed the readiness check. |
| Apply again | Nothing to add or replace in the folder or in Semaphore. |
| After the update | The API showed twelve templates on the tabs Lessons (5), Patching (3) and STIG (4), and three variable groups. Ping, the vendor STIG audit and the local SCAP content audit with DISA's RHEL 9 V2R9 benchmark succeeded against the RHEL target. |
| Fresh install | The Ubuntu installer seeded the three tabs with all twelve templates on them. Ping succeeded, and an update reported nothing to do. |
| Changed administrator password | Without a terminal, the script stopped with an explanation. With `SEMAPHORE_API_TOKEN`, it planned and applied. At a terminal it asked for a login and password: a wrong password stopped it with nothing changed, and the right one let it plan and apply. |

## Not established
