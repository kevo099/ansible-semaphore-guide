# Validation record: updating a controller, September 2026

[Back to validation and limits](../VALIDATION.md) · [Update a controller](../03-controller.md#update-a-controller-to-a-newer-guide-release)

On 28 September 2026, `scripts/update-controller.sh` and the seeder's template
tabs were tested on Azure in a disposable resource group, which was then
deleted.

## How it ran

- **Subscription and VMs:** the sponsored subscription of the
  [earlier Azure records](2026-09-azure.md), `eastus2`, `Standard_D2als_v6`.
- **Controllers:**
  - three AlmaLinux 9.8 VMs, each installed with the Enterprise Linux installer
    from tag `v1.4.0`, which seeds eleven templates, two variable groups and no
    tabs: the state of a controller installed before this release;
  - Ubuntu 24.04, installed with this branch's Ubuntu installer.
- **Target:** RHEL 9.8 pay-as-you-go, prepared with
  `examples/onboard/onboard-linux.sh` through Run Command with the controllers'
  service keys, and added to each with `add-target.sh`.

## Results

Every step below ran live; the controllers ran commit `4180b6a` of this branch
for the final runs, and every run's output was kept.

| Step | Result |
| --- | --- |
| Before the update | Ping succeeded through Semaphore. In the lab folder, `ansible.cfg` was changed to `forks = 1` and committed, and a playbook of the operator's own was committed. |
| Plan | Three files to update (`stig-apply.yml`, `stig-audit.yml`, `tasks/stig_scan.yml`), `ansible.cfg` kept as the operator's edit, eleven guide files current, `content/` to create; one variable group, three tabs and one template to add, eleven templates to put on tabs. Nothing changed. |
| Refusals | Each of these stopped the update with nothing changed in the folder or in Semaphore: a staged file; a committed edit to `stig-audit.yml`, which the release also changed; `content` as a link; an uncommitted deletion of `ansible.cfg`. |
| Apply | Saved the templates to a root-only file, added the Semaphore objects, updated the three files, kept `forks = 1` and the operator's playbook, created `content/`, and committed the three files with `.guide-files.json`. The readiness check passed. |
| Apply again | Compared with `.guide-files.json`: nothing to update or add, `ansible.cfg` still kept. |
| After the update | Twelve templates on the tabs Lessons (5), Patching (3) and STIG (4) and three variable groups; each template's prompts, limit, variable group and arguments matched the seeded settings. Ping, the vendor STIG audit and the local SCAP content audit with DISA's RHEL 9 V2R9 benchmark succeeded against the RHEL target. |
| A later release, simulated | With one playbook changed in the guide copy, the update swapped it in atomically on XFS (AlmaLinux) and ext4 (Ubuntu): owner the folder's editor, group `semaphore`, mode 0640, no temporary file left, and one commit of that file and `.guide-files.json`. A repeat changed nothing. |
| Revert | After `git revert` of an update commit, running the update applied it again, keeping `forks = 1`. |
| Fresh install | This branch's Ubuntu installer seeded the three tabs with all twelve templates on them, and Ping succeeded. |

Offline tests, run in CI, cover what the live runs could not stage: a release
that removes or renames a file, a file of the operator's at a new guide path, a
removed or uncommitted-deleted `.guide-files.json`, a reverted first update, an
edit made while Semaphore is updated or in the moment a file is swapped, a lab
folder path swapped for a link during the run, a template of the operator's
with a seeded name, a tab chosen during the run, a template save that fails,
an unconfirmed save left from an earlier run, and a missing Git e-mail.

## Found and fixed

Three adversarial reviews examined the updater before publication.

- The first found twelve problems in the first version, among them writes
  through predictable temporary names and links, a check that missed ignored
  and deleted files, a commit that took unrelated staged files, and a Semaphore
  login only after the folder had changed. The updater was rebuilt around a
  plan that checks everything first.
- A live run of the rebuild then showed a second update replacing a committed
  `ansible.cfg` change; updates now record the guide's versions in
  `.guide-files.json`.
- The second review found nine more, from a lab path swapped during the run to
  a failed template save, and the third found five that remained or were new:
  an edit saved in the moment a file was replaced, a partly failed save, the
  restore advice for a missing record, a template without variable groups
  treated as damaged, and the Ubuntu support claim. The updater now swaps files
  atomically and undoes the swap when the old file was not the planned one,
  records a template edit until it is confirmed, never changes variable groups,
  gives exact restore commands, and the chapter states which controllers it
  supports.
- Run as root from an administrator's copy of the guide, Python left
  root-owned bytecode in that copy; the updater no longer writes any.

## Not established

- Updating a controller installed from a release earlier than `v1.4.0`, or an
  Ubuntu controller from before `v1.5.0`, which the script refuses.
- The Semaphore web UI's display of the tabs; the checks read the API, which
  the UI uses.
