# Validation record: updating a controller, September 2026

[Back to validation and limits](../VALIDATION.md) · [Update a controller](../03-controller.md#update-a-controller-to-a-newer-guide-release)

On 28 September 2026, `scripts/update-controller.sh` and the seeder's template
tabs were tested on Azure in a disposable resource group, which was then
deleted.

## How it ran

- **Subscription and VMs:** the sponsored subscription of the
  [earlier Azure records](2026-09-azure.md), `eastus2`, `Standard_D2als_v6`.
- **Controllers:**
  - three AlmaLinux 9.8 VMs, each installed with the Enterprise Linux installer
    from tag `v1.4.0`, which seeds eleven templates, two variable groups and no
    tabs: the state of a controller installed before this release;
  - Ubuntu 24.04, installed with this branch's Ubuntu installer.
- **Target:** RHEL 9.8 pay-as-you-go, prepared with
  `examples/onboard/onboard-linux.sh` through Run Command with the controllers'
  service keys, and added to each with `add-target.sh`.

## Results

The final code ran on a third `v1.4.0` controller with every step's output kept.

| Step | Result |
| --- | --- |
| Before the update | Ping succeeded through Semaphore. In the lab folder, `ansible.cfg` was changed to `forks = 1` and committed, and a playbook of the operator's own was committed. |
| Plan | Three files to update (`stig-apply.yml`, `stig-audit.yml`, `tasks/stig_scan.yml`), `ansible.cfg` kept as the operator's edit, eleven guide files current, `content/` to create; one variable group, three tabs and one template to add, eleven templates to put on tabs. Nothing changed. |

| Apply | Saved the templates to a root-only file, added the Semaphore objects, then updated the three files as the folder's owner (mode 0640, group `semaphore`), kept `forks = 1` and the operator's playbook, created `content/` (mode 2750), and committed the three files with `.guide-files.json`. The readiness check passed. |
| Apply again | Compared with `.guide-files.json`: nothing to update or add, `ansible.cfg` still kept. |
| After the update | Twelve templates on the tabs Lessons (5), Patching (3) and STIG (4); three variable groups; every template's recovery prompt, host prompt, variable group and arguments unchanged. Ping, the vendor STIG audit and the local SCAP content audit with DISA's RHEL 9 V2R9 benchmark succeeded against the RHEL target. |
| Controllers updated by earlier drafts | A rerun recorded or used `.guide-files.json` and changed nothing else. |
| Fresh install | The Ubuntu installer seeded the three tabs with all twelve templates on them, and Ping succeeded. |

Offline tests cover what the live run could not stage: a release that removes or
renames a file, a file of the operator's at a new guide path, a removed
`.guide-files.json`, an edit made while Semaphore is updated, a lab folder path
swapped for a link during the run, a template of the operator's with a seeded
name, a tab chosen during the run, and a template save that fails or loses its
variable group, which the next run repairs from the backup.

## Found and fixed

- A first adversarial review found twelve problems, among them writes through
  predictable temporary names and links, a check that missed ignored and
  deleted files, a commit that took unrelated staged files, and a Semaphore
  login only after the folder had changed. The updater was rebuilt: it checks
  the folder and logs in before changing anything, writes through folder
  handles that never follow a link, commits only its own files, resolves the
  project by its lab folder repository and file inventory, and verifies each
  template it edits.
- A live run of the rebuild kept a committed `ansible.cfg` change once, but a
  second run replaced it, because it compared with the folder's last commit.
  Updates now record the guide's versions in `.guide-files.json`.
- A verification review then found nine more: the lab folder could be reached
  through a swapped parent path, an edit made during the Semaphore part could be
  overwritten, removals and renames were not planned, identical bytes adopted a
  file of the operator's, a removed record was silently replaced, a namesake
  template could be tabbed, a failed save was not repaired, a tab chosen during
  the run was overwritten, and a missing Git e-mail was found too late. All are
  fixed and covered by tests.
- Run as root from an administrator's copy of the guide, Python left
  root-owned bytecode in that copy; the updater no longer writes any.
